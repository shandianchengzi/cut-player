# 为了切完 18 小时的演唱会视频，我写了 Cut Player：一个支持波形定位和原码流导出的 Windows 分段播放器

有时候，写一个工具不是因为想做软件，而是手头的事情实在太麻烦了。

我去看了三场北京演唱会，而且每一场都不只用一台设备拍摄：三个设备一直在录，我又舍不得错过现场的任何一段。算下来，每场演唱会大约有 **6 小时待整理的视频**，三场就是 **18 小时**。每场还有 50 多首歌曲，加上开场、串场和谢幕，最后需要分割、命名的片段非常多。

这些视频不能只是粗略地裁成几段。我希望把每一首歌单独保存，知道它从什么时间开始、到什么时间结束；之后上传、分享或者回看时，可以直接找到想看的内容。另外，我还想单独保留现场录下来的音频，避免为了取得音频再进行一次有损编码。

所以我写了 **Cut Player**，一个专门用来**播放视频、标记时间、整理片段名称并批量导出**的 Windows 本地工具。三场演唱会的 18 小时素材，我已经用它完整切完了。

## 从 Quicker 小工具，到一个真正能边看边切的播放器

最早我其实没有打算单独开发播放器。当时已经用 Quicker 写了一个简单的离线分片工具，最终也是调用 FFmpeg 切割。麻烦的是，**切割之前的工作完全不连贯**。

我得先双击打开视频，在播放器里寻找歌曲开始的位置，再把时间记进记事本；一段一段看完、记录完之后，还要把记事本里的时间和名字复制到 Quicker，最后才真正执行 FFmpeg。

这个流程里，视频播放器、记录文本和切割程序是三个彼此分开的地方。切几段还好，但面对多个机位、18 小时的视频和上百个片段，反复切换窗口、复制粘贴就变成了最费事的环节。

我真正需要的不是复杂的剪辑软件，而是让这三个步骤待在同一个窗口里：**看到某个时刻 → 记下这个切点 → 给片段命名 → 直接导出**。因此最后还是做成了独立的 EXE 程序。

目前只支持 **Windows 10 / 11 x64**。这是我根据自己的使用环境做的选择，也没有计划迁移到其他平台。

## 打开多个视频，边播放边记录，不用来回复制时间

安装好后，可以点击「打开视频」、直接拖入文件，或者通过 Windows 右键「打开方式」导入。一次也可以打开多个视频，每个视频占一个标签页，各自保留播放位置、倍速和时间记录。

我切演唱会时最常用的操作，是一边播放一边寻找歌曲之间的分界。平时可以拖动进度条，配合音量波形寻找段落变化；想仔细听前后几秒，就用快捷键快进、快退。默认左右方向键每次移动 1 秒，长按可以连续移动；数字键 1～4 切换四档播放速度。快捷键、快进步长和倍速都能在「快捷键与倍速」里调整。

音量波形还能用鼠标滚轮缩放时间范围，点击波形即可定位。如果需要更细致地确定时间，可以打开「精细切割（逐帧）」，沿着视频帧逐步定位并记录毫秒级时间点。不过这里的「逐帧」指的是**播放定位与断点记录**，并不代表最后导出的片段一定逐帧精确，后面会解释原因。

找到切割位置后，点击「＋ 记录当前时间」，或者按默认快捷键 `Ctrl+Alt+V`，程序就把当前时间追加到右侧「时间记录」。时间点也会显示在波形上，回头检查边界方便得多。整套操作不用把时间反复复制到另一个程序里。

## 连文件名里的拍摄时间，也尽量替我算好

三个设备的素材经常需要按拍摄时间整理。手动给大量片段重新命名很容易出错，所以 Cut Player 会尝试从原视频文件名提取拍摄时间，再根据当前切点计算片段名称。

例如，假设导入的是一个 DJI 视频：

~~~text
DJI_20260925182823_0001_D.MP4
~~~

如果分别在 40 秒和 3 分 20 秒处记录切点，程序可以生成类似这样的两行文本：

~~~text
breakpoints:00:40,03:20
names:DJI_20260925182823x,DJI_20260925182903x,DJI_20260925183143x
~~~

这里是为了说明命名规则而构造的例子，不是某场演唱会的实际切点。第一行是视频内的绝对时间点，第二行依次对应三个输出片段；片段数量总是比切点数量多一个。它会按照 0～00:40、00:40～03:20、03:20～视频结束的顺序导出。

目前支持 DJI 日期时间式名称、常见的 `video_YYYYMMDD_HHMMSS` 名称（例如部分手机的视频文件名）、部分 Unix 时间戳形式。跨日时钟也会按日期继续计算。**这不是识别拍摄设备型号或自动识别歌曲**：它依靠的是文件名中的时间信息，无法识别的文件则使用相对时间后缀。

如果我想用曲名而不是时间来命名，直接修改 `names:` 这一行即可，例如：

~~~text
breakpoints:00:40,03:20
names:开场,修星星的人,串场
~~~

工具还内置了我此前整理过的一份周深北京演唱会曲目及串场名称列表。点击「导入名称」可以换成自己的列表；在文本框相应位置点击名称按钮即可插入曲名，不需要一首首重新打字。它只是**辅助插入名称**，不会自动分析音频并识别歌曲。

记录错了也能调整。「删除」可以选中某段记录并移除相应的名称和断点，时间区间会合并到相邻片段，**不会把源视频的那段内容删掉**。真的想重新开始时，才使用「初始化」。整份记录也能一键复制出来备份。

## 为什么我坚持用 FFmpeg 的 `-c copy`？

对演唱会视频来说，我最不想做的事情，就是把原本已经录好的音视频再压缩一遍。

因此，Cut Player 的视频分段采用 FFmpeg 的 **Stream Copy（码流复制）**：直接复制已有编码的数据包，不先把它解码、重新编码。这个处理方式不用反复猜测码率、编码器和质量参数，正常情况下也不会引入新一轮有损编码造成的画质和音质下降。

这也是我参考已有切割工具后最终确定的导出方案。需要强调的是：**码流复制保留的是原视频里已有的编码质量，并不会让拍摄时已经压缩或失真的画面、音频变得更好。** 此外，视频关键帧和时间戳会影响无重编码切割的实际边界，因而不能保证每一段严格从所记录的那一帧开始。精细模式可以帮助记录更准确的时间，但不会改变这一限制。

FFmpeg 官方也对这一机制进行了说明：[FFmpeg Documentation — Streamcopy](https://ffmpeg.org/ffmpeg.html#Stream-copy)。

除了切出视频，工具默认还勾选了「同时导出无损音频」。这表示**不重新编码音轨，直接提取源视频中的第一条音轨**，而不是把已经有损压缩的音频变成真正的无损录音。源音轨为 AAC 时会输出 `.aac`，其他编码一般封装为 `.mka`。我可以把这些音频另外存起来，后续听现场录音时就不必再从分享平台重新下载经过平台处理的版本。

## 切完之后，直接导出；原视频仍然留下

把切点和名称整理好后，点击右侧「切割」，选择输出文件夹即可。程序会按顺序导出各个片段，不需要再回 Quicker 粘贴一次记录。

导出过程中，可以看到当前片段的进度、文件大小、已导出视频的累计大小及累计时长。完成后，还会用 FFprobe 读取片段实际时长，并与原视频时长对照。这些信息对于处理很长的素材很有帮助：至少能及时发现明显的导出异常。不过，**总时长接近不能代替对每个切点的内容检查**。

现在也支持多视频标签页连续工作。比如正在导出第一个机位的视频，我可以切换标签去检查第二个机位、添加时间点和整理名称。当前导出任务使用启动时固定的源视频和记录，不会因为切到其他标签就换错素材。需要注意，**同时只执行一个导出任务**，并不是多个视频并行切割。

另外，程序不会为了节省空间而自动删除原始视频。这确实会多占一些磁盘空间，尤其当每场都有几个小时素材的时候；但万一某段切错、名字填错，原视频还在，才有机会重新处理。同名输出也会先询问是否覆盖，不能把输出直接覆盖到原视频上。

## 不想每次修个小问题，就重新下载整个安装包

我后续还在不断调整自己用得不顺手的小地方，比如长按快进快退、波形缩放、名称插入、快捷键以及多视频切换等。因此也做了更新功能。

在菜单中选择「帮助 → 检查版本更新」，就可以手动检查新版本。从支持差分更新的版本升级时，程序会优先利用本机已有安装包缓存，尝试只下载变化部分；如果缓存不足或差分失败，则会回退完整安装包下载。**差分更新是优先尝试，不保证每一次都只下载少量数据。**

视频和记录保存在本地，播放、记录和切割不需要把演唱会素材上传到服务器；联网主要用于下载安装与检查更新。应用自身已经包含必要的 FFmpeg / FFprobe 组件，正常安装后不需要用户另外配置命令行环境。

## 下载、使用范围与最后一点说明

Cut Player 不是专业非线性剪辑软件。我做它的目的很单纯：面对大量已经拍好的演唱会素材，快速找到歌曲与串场的分界，保留原有编码质量，批量切出便于保存和整理的片段。对于需要转场、调色、重新编码或严格逐帧精确剪辑的任务，它不是对应的解决方案。

当前仅发布 **Windows 10 / 11 x64 安装版**，不提供其他系统版本。安装包尚未进行代码签名；播放格式也取决于内置 Chromium 的解码能力，并非装有 FFmpeg 就能直接播放所有编码格式。

软件在许可范围内**非商业用途免费**。现行程序代码使用 PolyForm Noncommercial 1.0.0，商业用途需要另行授权；源码可以查看，但不是 OSI 意义上的开源软件。具体以 [许可证](https://github.com/shandianchengzi/cut-player/blob/main/LICENSE) 为准。
